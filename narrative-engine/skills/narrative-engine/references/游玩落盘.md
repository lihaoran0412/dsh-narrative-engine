# 游玩落盘

本文件规定游玩阶段的回合自动落盘与推翻机制。游玩规则本体在 `adult-tension-narrative` 技能，本文件只规定落盘格式。

## 回合自动落盘

**每回合游玩结束自动落盘**到 `playlog/turn_NN.yaml`，带**回合号 + 版本号**：

```yaml
turn: 78
version: 1                    # 版本号，推翻后递增
status: committed             # committed | superseded
clock: '2026-08-28T13:15:00+08:00'
player_action: "我走到她面前，把文件放在桌上"
npc_reaction: "她抬眼看了看文件，没接"
event_changes: []             # 事件/关系变化
scene: "小王健身房·器械区旁"
participants: [player-001, npc-001, npc-002]
safety_state: running
```

字段说明：
- `turn`：回合号，与 `meta.turn` 一致
- `version`：版本号，推翻后递增
- `status`：`committed`（有效）或 `superseded`（作废）
- `clock`：世界时钟（带时区 ISO 8601）
- `player_action`：玩家本回合动作
- `npc_reaction`：NPC 反应
- `event_changes`：事件/关系变化列表
- `scene` / `participants`：场景与参与者
- `safety_state`：安全状态

## 推翻机制（约束 1）

- 玩家说「刚才不算，改成 Y」→ 旧回合 `status: superseded`，新回合以新版本为准
- 具体操作：
  1. 旧回合文件标记 `status: superseded`，`version` 不变
  2. 新建同回合文件 `turn_NN.yaml`（`version` 递增，`status: committed`）或覆盖为新版本
  3. 写作阶段**只读 `status: committed` 的回合**，跳过 superseded，不会污染小说

## 字数档位（游玩）

游玩时玩家可设每回合输出长度：

```
字数 短     # 每回合 100-200 字，快节奏
字数 中     # 每回合 300-500 字，默认
字数 长     # 每回合 800-1200 字，沉浸
字数 超长   # 每回合 2000 字，极致沉浸
```

字数档位记录在 `state.json` 的 `play_length` 字段。

## 落盘时机

每回合游玩正文输出后、进入下一回合前，自动落盘。落盘是后台操作，不向玩家展示字段名或台账。

## 存档编辑稳定性

`manage_saves.py` 每次保存会**重新序列化 YAML**（引号格式变化），导致直接 `edit` 槽内文件频繁失败。遵循以下规则：

1. **编辑存档后立即重新落盘**：用 `manage_saves.py save` 把编辑后的 state.yaml 重新写回槽位，避免直接 edit 槽内文件。
2. **编辑前先读当前格式**：编辑前先 `read` 槽内 state.yaml，确认当前序列化格式，用匹配的格式 edit。
3. **不要反复重试同一 edit**：若 edit 因格式变化失败，先 read 最新内容，再 edit，不要盲目重试。
4. **用临时文件 + init 代替直接 edit**：需要大幅修改时，把 state.yaml 复制到临时位置编辑，再用 `manage_saves.py init` 重新初始化槽位。
