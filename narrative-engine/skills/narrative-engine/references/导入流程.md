# 导入流程

本文件规定小说导入为可游玩世界的完整流程：骨架提取、补全、玩家选择、切入点选择、v3 存档生成。

## 导入流程（对话式逐步确认）

```
第1步：玩家上传小说（支持多种来源，见 references/文件解析.md）
第2步：AI 解析正文 → 提取骨架 → 展示给玩家
第3步：玩家确认骨架（"这个角色设定对吗？""这个时间线对吗？"）
第4步：AI 列出「原文没写、需要补全」的空白清单 → 玩家选择补全程度
第5步：玩家逐项微调（"这个角色外貌改成这样""这个设定保留原样"）
第6步：玩家选择开局切入点（见下）→ 生成 v3 存档 → 进入游玩
```

## 骨架 vs 补全（核心区分）

| | 骨架（原文有的） | 补全（原文没写的） |
|---|---|---|
| 来源 | 小说白纸黑字写死的部分 | AI 生成的空白填充 |
| 处理 | **原样保留**，不加工不脑补 | AI 生成，玩家可选择 |
| 示例 | 角色姓名/年龄/身份/性格/目标/关系；世界观设定；事件先后；**文风** | 外貌细节、内心戏、决策轴、亲密画像、场景环境、处境压力、事件钩子 |

**关键**：骨架与补全分开，玩家才能控制"哪些保留原样、哪些让 AI 补全"。

## 风格提取（仿写原小说）

**原小说的文风是骨架的一部分**，应像世界观/角色卡一样被原样提取，供写作阶段仿写。风格提取产物写入 `style.md`：

```
style.md  文风档案（骨架，原样提取）
```

### 提取维度

| 维度 | 提取内容 |
|---|---|
| 叙事视角 | 第一/第三人称、全知/限知、是否切换视角 |
| 叙事人称 | 主角视角 / 旁观者视角 / 多视角 |
| 语言风格 | 文白夹杂/口语化/书面化/诗化、用词特色 |
| 句式节奏 | 长短句比例、段落密度、对话与描写的比例 |
| 描写风格 | 环境/心理/动作描写的侧重与方式 |
| 亲密场景写法 | 直白/含蓄、露骨程度、生理细节密度 |
| 对话风格 | 人物说话方式、口癖、语气 |
| 时间处理 | 顺叙/倒叙/插叙、时间跨度处理 |
| 氛围基调 | 冷峻/温暖/悬疑/情欲等整体氛围 |

### 风格决策（游玩前和写小说前各询问一次）

**风格决策发生在两个节点——游玩前和写小说前**，由玩家三选一：

| 风格选项 | 说明 |
|---|---|
| **A. 仿写原文风格**（默认） | 按 `style.md` 提取的原小说文风 |
| **B. 另有风格** | 玩家指定新风格（如"改成第一人称""换成冷峻文风"） |
| **C. AI 决定** | 由 AI 根据玩家推动的情节走向，自主选择最合适的风格 |

**两个节点可独立决策**：
- **游玩前**：玩家决定游玩阶段的叙述风格（`风格` 命令）
- **写小说前**：玩家决定写作阶段的文风（`风格` 命令），可与游玩前不同

> 默认是"仿写原文风格"（A），但**每次游玩前和写小说前都会询问玩家**，由玩家三选一，不默认跳过。

- 仿写只约束**表达方式**，不改变硬事实层（剧情/对话/事件结果）
- 亲密场景写法遵循 `adult-tension-narrative` 技能「性行为场景写法（硬约束）」，在所选风格前提下保持直白/露骨/过程可见

## 玩家选择项

| 选择项 | 玩家可以决定 |
|---|---|
| 保留原样 vs 补全 | 每个空白点：留白 or 让 AI 补全 |
| 补全程度 | 轻度（只补必需）/ 中度 / 重度（AI 自由发挥） |
| 逐项微调 | 对某个角色/设定不满意，玩家直接改 |
| 哪些角色进亲密线 | 只有玩家明确同意的角色才生成亲密画像 |
| 开局切入点 | 从小说哪个时间点开始游玩（见下） |

## 骨架提取效率（一次 grep 批量定位）

通读全书结构时，**用一次 `grep` 批量定位所有关键战役/人物/转折位置**，不要逐个搜索：

- 把需要定位的关键词（关键战役、关键人物、关键转折）**合并成一次 grep 正则**，一次返回所有位置。
- 例如：`grep -E "尧山之战|获鹿之战|北伐|菊花岛|岳飞|韩世忠" source.txt`
- 一次 grep 结果即可覆盖所有关键位置，避免逐个搜索浪费步骤。
- 只在 grep 结果不足、需要补充上下文时，才针对个别位置做二次读取。

## 提取产物

```
world_bible.md     世界观圣经（骨架 + 玩家允许的补全）
characters/        角色卡（骨架 + 玩家允许的补全）
timeline.md        时间线（骨架 + 玩家允许的补全）
outline.md         大纲骨架（主线从哪到哪、关键转折）
style.md           文风档案（骨架，原样提取，供仿写）
saves/…/state.yaml v3 存档（开局切入点，含安全不变量）
```

## 开局切入点选择

小说很长，玩家不可能逐字读完全文再选切入点。提供**三种互补的切入方式**，玩家任选其一：

### 方式 A：节拍点导航（推荐，最快）

AI 把小说切成"节拍点"列表（每点一句话摘要 + 时间/地点/角色/张力），玩家像翻目录一样选：

```
小说《示例》节拍点：
  [1]  开场：主角登场，进入故事起点
  [2]  第一个冲突：主角与关键角色相遇
  [3]  转折：核心事件发生
  [4]  高潮：矛盾升级
  ...
  [12] 尾声：主线收束
请输入编号选择切入点（如 4），或输入"续写"从结尾之后开始：
```

### 方式 B：场景搜索

玩家直接描述想切入的场景，AI 定位：

```
玩家：我想从"主角与关键角色相遇"那里开始
AI：  定位到节拍点 [2]，时间 <小说时间>，地点 <小说地点>，在场 <角色>
      确认从 [2] 开始游玩吗？
```

支持模糊匹配：时间（"从晚上开始"）、地点（"从健身房开始"）、事件（"从关键转折前开始"）、角色（"从某个角色出场开始"）。

### 方式 C：续写结局（从结尾之后开始）

玩家不想从小说中间切入，而是**续写新结局**：

```
玩家：续写
AI：  从小说结尾之后开始。当前状态：
      <小说结尾时的世界状态、人物关系、未决张力>
      未决：这段关系接下来往哪走？
      未决动作：停在玩家可接手的节点
```

续写时 `current_node` 设为小说结尾之后，`events` 保留小说遗留的未兑现事件，玩家从此自由发挥。

### 节拍点粒度

默认按"场景切换/事件转折"切分（每节拍约 1-3 个游玩回合的剧情量）。玩家可调粒度（`粒度 粗`/`粒度 细`）。

## 导入 → v3 存档的映射

导入提取的世界/角色/时间线必须映射进技能 v3 存档格式，才能被游玩引擎读取：

| v3 字段 | 来源 |
|---|---|
| `world.setting_shell`（时代/地点/规则/压力） | 骨架 |
| `world.constants` | 骨架 + 补全 |
| `world.tension_engines` | 骨架（2 项） |
| `player`（玩家化身） | 玩家指定（从小说主角或玩家自定） |
| `npcs[]`（角色卡） | 骨架 + 补全 |
| `relationships`（关系图） | 骨架 |
| `events`（事件队列） | 骨架 + 补全（immediate/near/far） |
| `current_node`（开局切入点） | 玩家选择的时间点 |
| `boundaries` / `consent` / `safety_state` | 安全不变量（18+/边界/同意） |

> 导入生成的存档必须通过 `validate_state.py --profile opening` 校验才能进入游玩。校验通过后进入 `adult-tension-narrative` 游玩引擎。
